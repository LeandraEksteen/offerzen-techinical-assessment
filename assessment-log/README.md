# Assessment log

Working notes kept while completing this take-home. Optional reading for reviewers.

- [`PROMPTS.md`](PROMPTS.md): every prompt given to the AI coding assistant, verbatim, in order, with a summary at the top.
- [`DECISIONS.md`](DECISIONS.md): numbered decisions (process and technical), with context and rationale.
- [`spec/`](spec/): the approved spec (`spec.md`, `requirements.yaml`) the tickets are built from.
- [`tickets/`](tickets/): `EPIC-1` and `TKT-1` to `TKT-12`, one groomed ticket per piece of work. Each PR links to its ticket.
- [`plans/`](plans/): the plan for each ticket (plan, contract, requirements, PR strategy) written before it was built, with implementation notes added afterwards.
- [`benchmarks/`](benchmarks/): the dashboard benchmark method and results, the page-1 snapshots, and the report outputs.
- [`../SOLUTION.md`](../SOLUTION.md): the design write-up; [`../README.md`](../README.md): how to run the app.

**Where to start:** the summary at the top of [`PROMPTS.md`](PROMPTS.md) describes how the work was done and what the author decided. The aim of this folder is to show the thinking and working method, not only the code.

Ground rules agreed up front:

1. No commits or PRs without the author's explicit permission.
2. No assumptions: unclear points are put to the author to decide.
3. Work is ticketed as if on a real team: one epic, one groomed ticket per task, one PR per ticket.
